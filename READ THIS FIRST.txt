THE FIX FOR "EVERYTHING WAS JUST CODE"
--------------------------------------

If the HUD widgets or the control panel came up showing raw HTML instead of a
graphic, that is fixed in this version, and the cause is worth knowing.

Windows keeps a list of content types in its registry. When a web page is
served, that list decides whether a browser treats the file as a page to render
or as text to display. Setting Notepad, or any editor, as the program that
opens .html files rewrites that registry entry to say .html is plain text. From
then on, every local page served by anything on that PC arrives as text and is
shown as code, with no styling and nothing loaded, which is exactly what you
saw.

PitWall no longer asks Windows. It states the content type of every file it
serves, so a machine in that state cannot break the overlays any more.

Two things worth doing anyway, because the same registry entry affects every
other local page on that PC:

  * Right-click any .html file, choose "Open with", then "Choose another app",
    pick Chrome or Edge, and tick "Always use this app".
  * After starting PitWall, open the Diagnostics tab in the control panel.
    There is a new check called "Windows content types" that reports whether
    this PC has the entry set correctly.

WHAT IS NEW IN 1.7.0
--------------------

THE COLUMN ENGINE
  Every list now draws from one set of column definitions: the broadcast tower,
  the in-car relative, the in-car leaderboard and the new ticker. A column means
  the same thing in all four. Thirty-two of them, all optional, in any order,
  with a width each.

  Add them to any widget with cols= in the URL, or build a layout in the control
  panel and reference it by name. Leaving cols= out keeps exactly the behaviour
  each page had before, so nothing you already have in OBS changes.

NEW COLUMNS
  Last pit lap, pit stationary time, total pit lane time, number of stops, tyre
  age, tyre compound, average of the last 3, 5 or 10 laps, positions gained
  against the grid, projected iRating change, estimated top speed, incidents,
  fast repairs, push to pass, licence, iRating, team, car, class and league tag.

  Columns that cannot mean anything in the current session remove themselves.
  Pit stops, tyre age and positions gained disappear in qualifying on their own.

TWO OF THEM ARE ESTIMATES, AND THEY SAY SO
  They are drawn in grey italic wherever they appear.

  Tyre age has no telemetry behind it. iRacing does not publish how old anyone's
  tyres are, so this counts laps since we last saw that car on pit road. A stop
  made before PitWall started is invisible, a car that pitted for fuel only
  still reads as fresh tyres, and a car outside your Max Cars limit can pit
  unseen. Until we have actually watched a car pit, the number is laps since we
  started watching, and hovering the cell says so.

  Top speed is inferred from how quickly a car covers track distance, because
  iRacing publishes speed for your own car and nobody else's.

  Tyre compound is real telemetry, but iRacing only fills it in for cars with
  more than one compound. In a single-compound GT3 field every car reports the
  same value, so the column shows a dash rather than inventing one.

  Other cars' tyre wear, tyre temperature and fuel load are not available to any
  overlay at all. Anything that appears to show them is showing your own car.

THE SCROLLING TICKER
  New browser source at 1920 x 64. The field crawling across the bottom of the
  frame, with the flag colour and LAP 14 / 40 pinned in a block on the left so
  they are never mid-scroll. The whole bar tints to the flag: green, yellow,
  white, chequered, red. In a timed session the block shows time remaining.
  Also a widget in the driver HUD.

PROFILES
  A saved layout, stored by the engine, referenced as ?profile=race-tower. Your
  OBS URLs stop being four hundred characters long, and a change reaches every
  source pointed at it without touching OBS. Anything written into a URL still
  wins, so a source you set up differently is never overruled.

  Build them in the control panel under the new Widgets tab: drag to reorder
  columns, a width each, colour pickers for every car state, and a live preview.

PER SESSION LAYOUTS
  A profile can carry different columns for practice, qualifying and the race.
  The swap happens on its own when the session changes. Nothing to reload.

DRIVER TAGS
  Tag a driver in the roster with a short label and a colour and their row
  stands out in every list. Tags live with the roster, so the whole league sees
  the same ones. The HUD always highlights the driver using it.

DRAG TO RESIZE IN THE HUD
  Ctrl+Shift+E to unlock, then drag the red corner grip of any widget to resize
  it. Text size is a separate control, so a wide leaderboard does not force
  enormous type. Sizes are still saved per screen arrangement.
