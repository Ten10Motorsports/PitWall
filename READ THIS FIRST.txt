PitWall 1.2.0  -  the whole thing, in one upload
================================================

This is every file, complete. You upload it ONCE and you are done.


STEP 1  -  EXTRACT THIS ZIP PROPERLY
------------------------------------
Right-click the zip  ->  Extract All...  ->  Extract.

This matters more than anything else on this page. If you drag files
straight out of the zip PREVIEW window, Windows strips the folder
information and everything lands loose in your repository with names like
"index (1).html". That is what went wrong before. Extracting first fixes it.


STEP 2  -  SHOW HIDDEN FILES
----------------------------
Open the extracted PitWall-1.2.0-EVERYTHING folder.

In the Explorer window:   View  ->  Show  ->  Hidden items   (tick it)

You should now see a folder called  .github  at the top of the list. If you
cannot see it, do not continue: without it the automatic build never runs.


STEP 3  -  SELECT EVERYTHING
----------------------------
Click once inside the folder, then press  Ctrl + A  to select all of it.

You should have 17 things selected: 8 folders and 9 files.

The 8 folders are:
    .github   config   docs   hud-app   scripts   server   site   web

This READ THIS FIRST.txt is one of the 9 files. Uploading it does no harm,
so there is no need to deselect anything.


STEP 4  -  UPLOAD
-----------------
   1. Open your repository on github.com
   2. Make sure you are at the TOP level (the address ends in the
      repository name, with no /tree/ after it)
   3. Click  Add file  ->  Upload files
   4. Drag the selected items from Explorer into the browser window


STEP 5  -  CHECK BEFORE YOU COMMIT   <-- the important bit
----------------------------------------------------------
GitHub now lists what it is about to upload. LOOK AT THAT LIST.

   CORRECT - the names have folders in front of them:

        server/main.py
        server/engine.py
        web/control/index.html
        web/broadcast/tower.html
        .github/workflows/release.yml

   WRONG - bare names with no folders, and numbered duplicates:

        main.py
        index.html
        index (1).html
        index (2).html

If it looks WRONG: do not commit. Leave the page without committing, go
back to Step 1, and make sure you extracted the zip first.

If it looks CORRECT: scroll to the bottom, type  PitWall 1.2.0  in the
description box, and click  Commit changes.

That is the whole upload. One commit, everything in place.


STEP 6  -  CHECK THE RESULT
---------------------------
On the Code tab you should see these folders and nothing loose:

    .github   config   docs   hud-app   scripts   server   site   web


STEP 7  -  MAKE THE RELEASE  (this builds the new PitWall.exe)
--------------------------------------------------------------
"Actions -> Run workflow" is NOT enough on its own. The .exe is only
attached to a release when the build is started BY A TAG, and creating
the release below is what makes the tag.

   1. On your repository, in the right-hand sidebar, click  Releases
      (or add  /releases  to the repository address)

   2. Click  Draft a new release

   3. Click the  Choose a tag  box and type:

            v1.2.0

      A line appears underneath saying "+ Create new tag: v1.2.0 on
      publish".  CLICK THAT LINE.  Skip it and no .exe will ever appear.

   4. Release title:   v1.2.0

   5. Leave the description empty. The build writes it for you.

   6. Leave "Set as a pre-release" unticked.

   7. Click  Publish release

   8. Click the  Actions  tab. A run called "Build Windows app" starts
      within a few seconds and takes three to four minutes.
      Orange dot = running.  Green tick = done.  Red X = failed, open it
      and send me what the failed step says.

   9. Green tick? Go back to Releases, click v1.2.0, and under  Assets
      you should now see:

            PitWall.exe
            PitWall-windows.zip

      If Assets only shows the two "Source code" entries, the build has
      not finished. Wait and refresh.


STEP 8  -  UPDATE THE RACE PC
-----------------------------
   1. Download PitWall.exe from the v1.2.0 release
   2. Close PitWall if it is running (close the black window)
   3. Drop the new PitWall.exe into C:\PitWall over the old one
   4. Double-click it

Your data folder sits BESIDE the .exe, so the roster, the cached track maps
and your league profiles are all kept. Nothing is lost.


WHAT IS NEW IN THIS VERSION
---------------------------
Practice and qualifying now work properly. The app reads the session type
and changes what it shows:

   * running order is quickest lap first, not track position
   * gap = how far off the quickest lap you are
   * the tower switches to BEST and LAST columns by itself, and switches
     back when the race starts
   * the session bar shows a countdown clock instead of Lap 7 / 42
   * the battle box hides itself, there is no fight to show

One set of OBS sources now covers practice, qualifying and the race with
no reloading in between.

Also included: the Leagues tab. Each league profile saves its name,
colours, roster URL and season calendar. One click applies the lot and
pulls the roster.

To try it without iRacing, open a command window in C:\PitWall (type cmd
in the Explorer address bar) and run, with two hyphens before each word:

    PitWall.exe --demo --scenario practice --speed 14
    PitWall.exe --demo --scenario qualify --speed 14
    PitWall.exe --demo --speed 14
