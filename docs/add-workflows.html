PitWall · Repair

Fix the repository upload

The upload put every file loose in the repository root with no folders. PitWall cannot run like that, and no amount of patching individual files will fix it. The repair is quick, but it means starting the upload again with a method that keeps folders intact.

How to tell this happened to you

Your file list contains numbered duplicates:

index (1).html ← web/control/index.html
index (2).html ← web/timing/index.html
index (3).html ← web/register/index.html
index (4).html ← web/hud/index.html
README (7).md ← docs/screenshots/README.md
standings (5).html← one of the two standings pages

PitWall has five different files called index.html and two called standings.html, each in its own folder. Strip the folders away and they collide, so the browser renamed them. Every one of those numbered files is now in the wrong place under the wrong name.

Why it happened, and why it is not your fault

Dragging files into GitHub's web uploader flattens them unless you drag the folders themselves. Selecting everything inside a folder and dragging that selection loses the structure completely.

It also silently skipped .github entirely, because folders starting with a dot are hidden in Windows Explorer.

Nothing is damaged. The zip on your computer is intact and correct.

Step 1

Clear out the mess

Deleting eighty files one at a time through the website is miserable. Do not do that.

The quickest clean slate is to delete the repository and make a new one. There is nothing worth keeping in it yet — no history, no issues, no releases.

  1. Repository Settings → scroll to the very bottom → Danger Zone → Delete this repository.
  2. Create a new one with the same name. Do not tick "Add a README file" — start it completely empty.
If you would rather keep the repository

Then use the GitHub Desktop or Git route in step 2. Both will delete the stray files for you as part of the push, so you do not have to click through them.

Step 2

Upload it again, with folders intact

Four routes. The first is the one to pick.

Route A — run the included script  fewest steps

The PitWall download contains setup-github.bat. It pushes this folder to GitHub exactly as it sits — folders, hidden files and all — so none of the flattening can happen.

  1. Create the empty repository on GitHub and copy its address from the green Code button. It ends in .git.
  2. Open the extracted PitWall folder and double-click setup-github.bat.
  3. Paste the address when it asks, type y, and wait.

It checks it is in the right folder, warns you if .github is missing before it starts, and prints what to do next when it finishes.

It needs Git, and will tell you if you do not have it

If Git is missing the script stops and gives you the one-line command to install it. Paste that into a Command Prompt, then run the script again:

winget install --id Git.Git -e

On macOS or Linux, use setup-github.sh in the same folder instead.

Route B — GitHub Desktop

Free, no command line, and it handles folders and hidden files correctly. Ten minutes once, then every future update is two clicks.

  1. Install GitHub Desktop and sign in.
  2. File → Clone repository, pick your empty repository, and note the folder it clones into.
  3. Extract the PitWall zip. Open the extracted pitwall folder so you can see server, web, run.bat and the rest.
  4. Select all of it and copy it into the cloned folder. If anything from the old upload is in there, delete it first.
  5. Back in GitHub Desktop you will see a long list of changes. Type a summary such as PitWall, click Commit to main, then Push origin.
This route handles .github for you

GitHub Desktop does not hide dot-folders, so the automation goes up with everything else and you can skip step 4 entirely.

Route C — Git command line, by hand

If you already have Git, this is the fastest path. Run it inside the extracted pitwall folder:

git init
git add -A
git commit -m "PitWall"
git branch -M main
git remote add origin https://github.com/YOUR-ORG/YOUR-REPO.git
git push -u origin main --force

Replace the URL with your own. The --force overwrites whatever is up there, which is exactly what you want here.

Route D — the website, done correctly

It does work, as long as you drag folders rather than their contents.

  1. In the empty repository, click uploading an existing file.
  2. Open the extracted pitwall folder in Explorer.
  3. Select the folders — config, docs, hud-app, scripts, server, site, web — plus the loose files, and drag them in as one go. Do not open the folders and drag what is inside them.
  4. Commit.
This route will still miss the automation

The .github folder is hidden and the web uploader skips it. If you take route D you must also do step 4 below.

Step 3

Check it looks right

Thirty seconds, and it saves you finding out later.

Open the Code tab. The root should show folders, not a wall of loose files:

PitWall/
├── .github/          ← the automation. Hidden by the leading dot.
│   ├── ISSUE_TEMPLATE/
│   └── workflows/
├── config/
├── docs/
├── hud-app/
├── scripts/
├── server/           ← the engine. Python needs this folder to exist.
├── site/
├── web/              ← every overlay and page
│   ├── broadcast/
│   ├── control/
│   ├── hud/
│   ├── register/
│   ├── shared/
│   └── timing/
├── .gitignore
├── README.md
├── roster.json
├── run-demo.bat
├── run.bat
└── run.sh
  • You should see about eight folders and five loose files. No .py files at the root. No .html files at the root.
  • Nothing with a number in brackets. If index (1).html is still there, the upload flattened again.
  • Click into server — it should hold main.py, engine.py, irsdk.py and friends.
  • Click into web — it should hold broadcast, control, hud, register, shared, timing.
On not seeing .github

GitHub does show it in the file list even though your computer hides it. If it is not there, you took route D and need step 4.

Step 4

Add the automation, only if it is missing

Skip this entirely if you used routes A, B or C — those all upload .github for you.

Four files. For each one: Add file → Create new file, paste the path into the filename box, paste the contents into the editor, Commit changes.

Typing the / characters in the filename makes GitHub create the folders for you — which is what gets around the hidden-folder problem.

Two things that will bite you

Keep the leading dot on .github. Without it nothing runs.

Use the Copy button, not a manual selection. These are YAML, where indentation carries meaning, and a stray space breaks the file.

Publish site

Publishes your league page, the handbook and the showroom to GitHub Pages.

# Publishes the league's public pages: the setup handbook, the live showroom,
# and a landing page with the sign-up link and the current roster.
#
# Static hosting only — no server, no data. The live timing feed comes from
# whoever is running PitWall.exe, not from here.

name: Publish site

on:
  push:
    # Covers repos whose default branch is either name. A workflow that only
    # watches "main" silently never runs on a "master" repo.
    branches: [main, master]
    paths:
      - 'docs/**'
      - 'site/**'
      - 'roster.json'
      - '.github/workflows/pages.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Assemble the site
        run: |
          mkdir -p _site
          cp -r site/* _site/ 2>/dev/null || true
          cp docs/setup-guide.html _site/setup.html 2>/dev/null || true
          cp docs/preview.html     _site/preview.html 2>/dev/null || true
          cp roster.json           _site/roster.json 2>/dev/null || echo '{"drivers":[]}' > _site/roster.json
          # GitHub Pages runs Jekyll unless told not to, which eats folders
          # starting with an underscore.
          touch _site/.nojekyll
          ls -la _site

      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: _site }

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deploy.outputs.page_url }}
    steps:
      - id: deploy
        uses: actions/deploy-pages@v4

Build Windows app

Builds PitWall.exe on a Windows runner, tests that it starts, and attaches it to a release.

Filename to type .github/workflows/release.yml .github/workflows/release.yml
113 lines · paste all of it 
# Builds PitWall.exe on GitHub's Windows runners and attaches it to a release.
#
# The point: nobody in your league installs Python, unzips anything, or ticks
# a PATH checkbox. They download one file and double-click it.
#
# To cut a release:  git tag v1.0.0 && git push --tags
# Or run this workflow by hand from the Actions tab.

name: Build Windows app

on:
  push:
    tags: ['v*']
  workflow_dispatch:

permissions:
  contents: write

jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      # PitWall itself has no dependencies. PyInstaller is only needed to
      # produce the .exe, and only here on the build machine.
      - name: Install PyInstaller
        run: python -m pip install --upgrade pip pyinstaller

      - name: Build
        run: python scripts/build_exe.py

      - name: Smoke test the build
        shell: pwsh
        run: |
          # Start the app in demo mode and prove it actually serves before we
          # ship it. A release that does not start is worse than no release.
          $p = Start-Process -FilePath "dist\PitWall.exe" `
               -ArgumentList "--demo","--no-browser","--port","8123" `
               -PassThru -WindowStyle Hidden
          Start-Sleep -Seconds 12
          try {
            $r = Invoke-WebRequest -Uri "http://127.0.0.1:8123/api/status" -UseBasicParsing -TimeoutSec 15
            if ($r.StatusCode -ne 200) { throw "status endpoint returned $($r.StatusCode)" }
            $j = $r.Content | ConvertFrom-Json
            if (-not $j.connected) { throw "demo feed did not connect" }
            Write-Host "OK - served $($j.ticks) ticks"

            foreach ($path in @('/control','/timing','/register','/broadcast/tower.html','/hud/relative.html')) {
              $pr = Invoke-WebRequest -Uri "http://127.0.0.1:8123$path" -UseBasicParsing -TimeoutSec 10
              if ($pr.StatusCode -ne 200) { throw "$path returned $($pr.StatusCode)" }
              Write-Host "OK - $path"
            }
          } finally {
            Stop-Process -Id $p.Id -Force -ErrorAction SilentlyContinue
          }

      - name: Package
        shell: pwsh
        run: |
          New-Item -ItemType Directory -Force -Path package | Out-Null
          Copy-Item dist\PitWall.exe package\
          Copy-Item README.md package\
          Copy-Item docs\setup-guide.html package\ -ErrorAction SilentlyContinue
          Copy-Item docs\preview.html package\ -ErrorAction SilentlyContinue
          New-Item -ItemType Directory -Force -Path package\config | Out-Null
          Copy-Item config\pitwall.example.json package\config\
          # A PowerShell here-string cannot be indented, and YAML block
          # scalars require indentation, so build the file from an array.
          @(
            'PitWall',
            '',
            '1. Double-click PitWall.exe',
            '2. Your browser opens the control panel',
            '',
            'That is the whole install. No Python, no setup.',
            '',
            'To look around without iRacing running, open a command prompt here and run:',
            '    PitWall.exe --demo --demo-roster',
            '',
            'setup-guide.html  - full setup walkthrough, open it in a browser',
            'preview.html      - see every graphic working, no sim needed'
          ) | Set-Content -Path package\START-HERE.txt -Encoding UTF8
          Compress-Archive -Path package\* -DestinationPath PitWall-windows.zip -Force

      - uses: actions/upload-artifact@v4
        with:
          name: PitWall-windows
          path: PitWall-windows.zip
          retention-days: 90

      - name: Attach to the release
        if: startsWith(github.ref, 'refs/tags/')
        uses: softprops/action-gh-release@v2
        with:
          files: |
            PitWall-windows.zip
            dist/PitWall.exe
          generate_release_notes: true
          body: |
            ## Install

            Download **PitWall.exe**, put it in a folder, double-click it.

            No Python. No setup. Nothing else to install.

            Only one person in a league needs this — whoever is spectating or
            driving in the session. Everyone else opens a web page.

Driver sign-ups

Reads driver sign-up issues and keeps roster.json up to date.

Filename to type .github/workflows/roster.yml .github/workflows/roster.yml
95 lines · paste all of it 
# Turns driver sign-up issues into roster.json.
#
# A driver opens the "Driver sign-up" issue form, this reads it, updates
# roster.json and commits. They install nothing. Editing the issue re-runs it,
# so fixing a typo needs no new submission and no admin.

name: Driver sign-ups

on:
  issues:
    types: [opened, edited, reopened]
  workflow_dispatch:

permissions:
  contents: write
  issues: write

jobs:
  roster:
    # Only sign-up issues; ignore everything else in the repo.
    if: github.event_name == 'workflow_dispatch' || contains(github.event.issue.labels.*.name, 'driver-signup')
    runs-on: ubuntu-latest
    concurrency:
      # Two drivers submitting at once must not race each other's commit.
      group: roster-write
      cancel-in-progress: false
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Read the submission
        env:
          BODY: ${{ github.event.issue.body }}
        run: printf '%s' "$BODY" > /tmp/body.md

      - name: Update the roster
        id: build
        run: |
          set +e
          python scripts/roster_from_issue.py \
            --body-file /tmp/body.md \
            --out roster.json \
            --issue "${{ github.event.issue.number }}" \
            --user "${{ github.event.issue.user.login }}" \
            --comment-file /tmp/comment.md
          echo "rc=$?" >> "$GITHUB_OUTPUT"

      - name: Commit
        if: steps.build.outputs.rc == '0'
        run: |
          git config user.name "pitwall-bot"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          if git diff --quiet -- roster.json; then
            echo "roster unchanged"
            exit 0
          fi
          git add roster.json
          git commit -m "Roster: sign-up from #${{ github.event.issue.number }}"
          # Another sign-up may have landed while this one ran.
          for i in 1 2 3 4 5; do
            git pull --rebase --autostash origin "${GITHUB_REF_NAME}" && git push && exit 0
            echo "push race, retrying ($i)"
            sleep $((RANDOM % 5 + 2))
          done
          echo "could not push after 5 attempts"; exit 1

      - name: Reply on the issue
        if: always() && github.event_name != 'workflow_dispatch'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          if [ -f /tmp/comment.md ]; then
            gh issue comment "${{ github.event.issue.number }}" \
              --repo "${{ github.repository }}" --body-file /tmp/comment.md
          fi

      - name: Close it once accepted
        if: steps.build.outputs.rc == '0' && github.event_name != 'workflow_dispatch'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh issue close "${{ github.event.issue.number }}" \
            --repo "${{ github.repository }}" --reason completed || true

      - name: Reopen if it was rejected
        if: steps.build.outputs.rc != '0' && github.event_name != 'workflow_dispatch'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh issue reopen "${{ github.event.issue.number }}" \
            --repo "${{ github.repository }}" || true

Step 5

Switch it on

Two settings and two button presses.

  1. Settings → Actions → General → Workflow permissions → choose Read and write permissions → Save. Sign-ups cannot save the roster without this.
  2. Settings → Pages → Source → choose GitHub Actions. Ignore the two "Configure" cards it offers — those would add a competing workflow.
  3. Actions tab → Publish site → Run workflow. Under a minute, and your league page is live.
  4. Actions tab → Build Windows app → Run workflow. About three minutes, and the app download works.
You are done when

The Actions tab lists Publish site, Build Windows app and Driver sign-ups down the left instead of the "Get started with GitHub Actions" page, and both runs you triggered show a green tick.

Every file shown on this page is also in the PitWall download under .github/. The contents are identical — this page just saves you finding a folder your computer is hiding.
