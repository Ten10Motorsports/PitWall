Why anyone needs the app at all

iRacing publishes its live timing data into memory on the computer running the sim. No website can reach that, including GitHub. So one program has to run on a PC that is in the session — but only one, and everyone else just opens pages it serves.

Part A

League admin, once

About twenty minutes. You never do this again.

01 Put it on GitHub

This repository becomes your league's sign-up desk, roster and download page.

Create a new repository on GitHub, then push the PitWall folder into it. Public or private both work — public is easier, because drivers can then use the sign-up form without being added as collaborators.

In the PitWall folder
git init
git add .
git commit -m "PitWall"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
git push -u origin main
Easier: let the included script do it

Double-click setup-github.bat in the PitWall folder, paste your repository address when it asks, and it pushes everything correctly. On macOS or Linux use setup-github.sh.

Use this rather than dragging files into the GitHub website. The web uploader flattens every folder and skips .github because Windows hides names beginning with a dot — which leaves you with a root full of loose files named index (1).html and no automation at all. GitHub Desktop also works correctly if you prefer buttons.

One setting to change before anything else

Go to Settings → Actions → General, scroll to Workflow permissions, and choose Read and write permissions. Save.

Without this the sign-up system cannot save the roster or reply to drivers, and it fails with a permissions error that is not obvious.

02 Switch on Pages

This publishes your league's public page.

Settings → Pages → Source, and choose GitHub Actions.

Do not click either "Configure" button

As soon as you pick GitHub Actions, the page offers you two cards — GitHub Pages Jekyll and Static HTML — each with a Configure button. Ignore both.

Those are templates for people starting from nothing. PitWall already ships its own workflow at .github/workflows/pages.yml. Clicking Configure would add a second, competing one.

Choosing GitHub Actions in that dropdown is the entire configuration. There is nothing else on this screen to set.

Now make it publish

The line reading "Workflow details will appear here once your site has been deployed" means it has not run yet. If you switched Pages on after pushing your code — which most people do — the first run either never fired or failed, because Pages was still off.

Kick it off by hand, once:

  1. Open the Actions tab at the top of your repository.
  2. Click Publish site in the left-hand list.
  3. Click Run workflow on the right, then Run workflow again to confirm.

It takes under a minute. A green tick means you are done, and from then on it republishes automatically whenever you change anything.

Your league page is then live at:

https://YOUR-NAME.github.io/YOUR-REPO/

It carries the sign-up form, the app download, this handbook, the showroom, and a live entry list that fills in as drivers register.

Nothing to configure in the page itself

The page works out which repository it belongs to from its own address, so there is no config file to edit and no links to paste in. It just works once Pages is on.

If Actions has no "Publish site" entry at all

Then the .github folder did not reach GitHub. It starts with a dot, so some upload methods and file browsers hide it. Check that .github/workflows/ exists in your repository, and push it if not:

git add -f .github
git commit -m "Add workflows"
git push

03 Build the app

GitHub compiles it for you. You do not need Python or a build tool.

Cut the first release
git tag v1.0.0
git push --tags

Or, without the command line: open the Actions tab, choose Build Windows app on the left, and click Run workflow.

GitHub then, on a Windows machine it provides:

  1. Compiles PitWall into a single PitWall.exe.
  2. Starts it and checks it actually serves pages.
  3. Attaches it to a release, but only if step 2 passed.

Takes about three minutes. When it is done, the download button on your league page works.

Why the build tests itself

A release that does not start is worse than no release, because you find out on race night. This one fetches the status endpoint and five pages from the built executable before it will publish it. If that fails, the release simply does not appear and the Actions log says why.

To ship an update later, tag a new version. Everyone downloads from the same link and their roster, settings and cached track maps survive, because those sit next to the executable rather than inside it.

04 Link the roster

So every copy of the app sees the same drivers.

Create config/pitwall.json in the repository (copy config/pitwall.example.json) and set the roster block to point at your own repository:

{
  "league": {
    "name": "Your League",
    "accent": "#e8443a"
  },
  "roster": {
    "mode": "url",
    "url": "https://raw.githubusercontent.com/YOUR-NAME/YOUR-REPO/main/roster.json",
    "autoPullSeconds": 300
  }
}

Now whoever runs the broadcast in a given week automatically has every driver's photo, flag and bio, refreshed every five minutes. There is also a Pull button on the control panel's Roster tab.

Put this file next to the .exe

When people run the downloaded app, it looks for config/pitwall.json in the folder beside PitWall.exe. Include that folder when you tell people what to download, or paste the settings into the League tab of the control panel instead, which writes the same file.

05 Send one link

This is your entire onboarding message.

Post your Pages URL in your league Discord. Something like:

Suggested wording
Sign up for the broadcast here:
https://YOUR-NAME.github.io/YOUR-REPO/

Takes two minutes and you only ever do it once. You need your
iRacing CUSTOMER ID - the number under Account > My Account
> Customer ID on the iRacing website. Not your name, not your
car number.

Nothing to install.

Say the customer ID part explicitly. It is the single field people get wrong, and every wrong one is a driver whose card does not appear on the broadcast.

Part A is done. You never repeat it.

Part B

Whoever runs the broadcast

The only person who installs anything. About fifteen minutes the first time.

06 Get the app

One file. No Python, no installer, no setup wizard.

  1. Open the league page and click Download the latest release.
  2. Download PitWall-windows.zip and extract it somewhere sensible, like C:\PitWall.
  3. Double-click PitWall.exe.

A console window opens and your browser opens the control panel. That is the install.

Two things Windows may do

SmartScreen may say "Windows protected your PC" because the file is not code-signed. Click More info then Run anyway. Code signing certificates cost several hundred pounds a year, which is why small tools rarely have one.

Do not extract into Program Files. Windows will block the app writing its roster and settings there. A plain folder on your C: drive is best. Avoid a OneDrive-synced folder too, since sync can lock files mid-race.

Leave the console window open while you race. Closing it stops PitWall. To stop it deliberately, click it and press Ctrl + C.

07 Look around without iRacing

Build your whole OBS scene collection with the sim closed.

Open a command prompt in the PitWall folder and run:

PitWall.exe --demo --demo-roster --speed 14

That runs a synthetic twenty-four car, two-class race, compressed so a full race takes about five minutes. Pit stops, a safety car, a fight for the lead, a chequered flag. Every graphic behaves exactly as it will on race night.

Do your setup here, not on race night

Build your scenes, pick your colours and check every graphic against this. Then on race night the only new thing being tested is whether the telemetry connects, rather than whether your lower third is the right colour.

There is also preview.html in the download — a full race running in your browser with nothing started at all. Useful for showing people what the broadcast will look like.

Find your way around the control panel

08 Prepare iRacing

Four settings. Three are one-time.

1. Max Cars, on the iRacing website

Go to members.iracing.com → Account, and set Max Cars to 63. Also set your connection to 1 Mbit/s or faster.

Why this one matters

Below 63, iRacing does not send reliable position data for the back of the field. No timing tool can invent it. If cars at the tail flicker or vanish, this is almost always the reason.

2. Display mode — only if you want the in-game HUD

In iRacing: Options → Graphics. Turn Full Screen off and Border off, then restart iRacing. Changing it without restarting often leaves a border behind.

If you race in VR, read this

The in-game HUD cannot work in VR, and that is not something I can fix in code. A headset's compositor never sees desktop windows, so no overlay of this kind can appear inside it.

Use the second-screen timing page on a phone or tablet instead — it shows more than a HUD would anyway. Your OBS broadcast graphics are completely unaffected and work in any display mode, VR included.

If you only want the broadcast graphics and the timing page, skip this step. Exclusive fullscreen is fine for those.

3. Telemetry — check it is on

Almost always already correct. Open Documents\iRacing\app.ini in Notepad and find irsdkEnableMem:

irsdkEnableMem=1

If it is 0, change it to 1 and restart iRacing. Diagnostics checks this for you.

4. Display scaling — only for the in-game HUD

Windows Settings → System → Display → Scale should be 100%. At 125% or higher, HUD positions drift.

09 Go live

One double-click.

  1. Start iRacing and get into a session — a test drive, a practice session, or a replay all work.
  2. Double-click PitWall.exe.
  3. Open the control panel's Status tab.

The big tile should read Connected to iRacing with your track and session below it.

If it says connected

Setup is done. Every overlay, the timing page and the HUD now have real data. On to step 10.

If it does not

Click Diagnostics. It checks the real causes and names the one affecting you — not in a session, telemetry disabled, an elevation mismatch, and so on — each with its specific fix.

This tab exists because "I installed it, nothing appeared, and the app said nothing" is the standard experience with overlay software. Read what it tells you rather than searching forums.

You can start PitWall before or after iRacing, in either order. It watches for the sim, connects when it appears, and reconnects on its own when you move between sessions. Leave it running all evening.

10 Set up OBS

Each graphic is a Browser source. Nothing to install in OBS.

Sources → + → Browser. For each one, paste the URL and set Width and Height from this table.

GraphicURLWH
Timing towerhttp://127.0.0.1:8099/broadcast/tower.html4601080
Session bar.../broadcast/session-bar.html1920120
Driver card.../broadcast/driver-card.html?auto=119201080
Battle box.../broadcast/battle.html?max=1.519201080
Track map.../broadcast/trackmap.html600600
Standings board.../broadcast/standings.html19201080

Leave "Shutdown source when not visible" unticked. The graphics reconnect by themselves, but keeping them alive avoids a visible flash when you cut to a scene.

Do not resize the full-frame graphics

The driver card, battle box and standings board are 1920×1080 and position themselves inside that frame. Drop them at 0,0 and leave them. To move one to a different corner, add ?pos=br (or tl, tr). Scaling a browser source makes the text soft.

A scene layout that works

Race scene — your iRacing capture, plus:

  • Session bar at the top, position 0,0
  • Tower down the left, position 0,120
  • Driver card at 0,0 with ?auto=1
  • Battle box at 0,0 with ?max=1.5
  • Track map bottom right
Set these two and forget them

The driver card with ?auto=1 appears for eight seconds whenever you cut to a new car, then hides. The battle box hides unless there is a real fight closer than 1.5 seconds. Leave both in the scene permanently and never touch them mid-race.

Pre-race and results — use the standings board over a holding graphic. It re-titles itself to RESULTS and promotes the podium automatically at the chequered flag, so one source covers both.

If the tower is on the left, move the driver card

They both want the bottom-left corner and will overlap. Either put the card bottom-right with ?pos=br, or start it clear of the tower.

Customising a graphic

Options go on the end of the URL. The Overlays tab has a builder that writes them with a live preview. For example, intervals plus last lap, grouped by class, slightly enlarged:

http://127.0.0.1:8099/broadcast/tower.html?rows=16&col=int&col2=last&group=class&scale=1.1

Full list in the reference table.

11 The second screen

Full timing on a laptop, tablet or phone. Nothing installed on that device.

On the Status tab, find On your network. It lists an address like:

http://192.168.1.24:8099/timing

Type that into a browser on any device on the same network. That is it.

Use the network address, not 127.0.0.1

127.0.0.1 means "this machine" and will never work from another device. Copy the address from the On your network section.

The first time, Windows will ask whether to allow PitWall through the firewall. Say yes, with "Private networks" ticked. If you clicked Cancel, go to Windows Defender Firewall → Allow an app through firewall and find it there.

Other things that block it: the two devices being on genuinely different networks (a guest network usually blocks device-to-device traffic entirely), or client isolation on the Wi-Fi.

The page reflows into a card list on a phone, so it is usable one-handed. Tap any car for its full profile, lap history and lap-time chart.

Remote viewers

For someone in another house — a co-commentator, stewards watching from home — you need a tunnel from the broadcast PC. Tailscale or Cloudflare Tunnel are both free and about a one-line setup, and give an address that works from anywhere. This is the one part of the system that is not covered by GitHub.

12 Director controls

Drive iRacing's camera from the control panel.

The Sim control tab gives you: cut to a specific car, to the leader, to the most exciting battle, or to the last incident; pick a camera group; jump to the previous or next incident in the replay; jump back to live; change replay speed; trigger screenshots.

This is iRacing's own interface

These use the remote-control channel iRacing publishes for exactly this. Nothing is injected into the game and no memory is written. PitWall only ever reads the sim.

If the buttons do nothing

If iRacing runs as administrator and PitWall does not, Windows silently discards these commands — no error, nothing happens. Run both the same way, ideally neither elevated. Diagnostics flags this.

Part C

Drivers

Two minutes, once, and nothing to install.

13 Sign up

This is what your drivers do. Send them this section.

Open the league page and click Sign up. Fill in the form and submit. That is all.

What you can add:

  • iRacing customer ID and name — required
  • Car number, team, country (for your flag)
  • A headshot — drag an image straight into the box and it uploads
  • Pronouns, hometown, a one-line bio for the commentary team
  • Twitch, YouTube, Instagram, X, Discord
  • A sponsor and logo, and an accent colour for your card
The customer ID is the field everyone gets wrong

It is the number on the iRacing website under Account → My Account → Customer ID. Numbers only. It is not your display name and not your car number.

Everything joins on this, so a wrong one means your card never appears on the broadcast. If you put something else in, the form will reject it and tell you.

Within a minute you get a reply listing exactly what was recorded, and your name appears on the league page's entry list.

Changing your entry

Edit your own submission and it updates automatically. No new form, no asking an admin, and no duplicate entry — matching is on your customer ID, so re-submitting replaces rather than adds.

Why the customer ID and not your name

Names change, and in team endurance races the driver in the car changes mid-stint. The customer ID is the only key that survives both.

14 The in-game HUD

Optional, and only for drivers who want overlays on their own screen.

Six transparent widgets that sit over iRacing: relative, standings, pedal trace, fuel and tyres, delta bar, and a flag and spotter strip.

Download the same PitWall.exe, run it on your own PC while you drive, and add the HUD pages as overlays. For proper transparent always-on-top windows, the HUD shell in hud-app/ needs Node.js:

One time
cd hud-app
npm install
Each time, after PitWall is running
npm start
KeyDoes
Ctrl + Shift + EUnlock the widgets to drag and resize. Press again to lock.
Ctrl + Shift + HHide or show everything.
Ctrl + Shift + RReload all widgets.

The tray icon next to the clock toggles individual widgets. Positions save automatically.

Why they go click-through when locked

Locked widgets ignore the mouse entirely, so a click meant for the sim can never be swallowed by an invisible overlay on top of it. That is a mistake every overlay tool makes at least once, and it is infuriating mid-race.

Requirements

iRacing must be in windowed or borderless mode, and this does not work in VR (see step 8). If either applies, put the timing page on a phone or tablet instead, or add the same widgets as OBS sources on a second monitor.

Why gaps go blank under yellow

Under caution the field is bunched behind a pace car, and a gap calculated from lap distance describes nothing real. Same for delta on any lap that touched pit lane — a car sitting in its box accumulates lap time without accumulating distance, which is how other tools end up showing a delta of +200 seconds.

PitWall shows a dash instead. A number you cannot act on is worse than no number, on a broadcast most of all.

∞ What a WebSocket is

Nothing to set up. It is just how the pieces talk.

An ordinary web page works like posting a letter. Your browser asks the server for something, gets it, and the conversation ends. To find out whether anything changed, it has to ask again. And again.

Fine for a news article. Useless for a timing tower that changes fifteen times a second.

A WebSocket is a phone call instead. The browser dials once, the line stays open, and either end talks whenever it has something to say.

  • Your tower and timing page cannot disagree. The gaps are worked out once and the same numbers go to everything. There is no second copy of the maths to drift.
  • Any device works. WebSockets are a standard browser feature, which is why your phone needs nothing installed.
  • It heals itself. Restart PitWall mid-session and every graphic reconnects within a couple of seconds. You do not touch OBS.

← Without GitHub

If you would rather not use GitHub at all.

Everything works standalone. You lose the automatic build, the shared roster and the public sign-up page, and you gain a Python install.

  1. Install Python 3.9 or newer from python.org. Tick "Add python.exe to PATH" during setup.
  2. Unzip PitWall somewhere sensible.
  3. Double-click run.bat, or run-demo.bat to look around without iRacing.

Sign-ups then use the app's own form. Send drivers the address on the Status tab, ending in /register, while PitWall is running. The roster is saved locally in data/roster.json, which you can export and share by hand.

Steps 8 to 12 of this guide apply unchanged.

You can also build the .exe yourself:

pip install pyinstaller
python scripts/build_exe.py

PitWall reads iRacing through the SDK iRacing publishes for this purpose, read-only. Nothing is injected into the sim, no graphics API is hooked, and no game files are modified. Camera and replay control use irsdk_broadcastMsg, iRacing's own remote-control interface.
