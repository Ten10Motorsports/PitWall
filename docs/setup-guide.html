Part A

On GitHub

Once, from any computer. Nothing to install.

A1 Push the files

Done. Your repository shows folders — server, web, docs and the rest.

A2 Add the workflow files

Done. Four files under .github.

To double-check at any time: click the Code tab and confirm a .github folder is listed. Inside it, workflows holds three files and ISSUE_TEMPLATE holds one.

A3 Turn on two settings

Do this before running anything. Two minutes.

Setting 1 — let the workflows write

  1. On your repository page, click Settings in the top row of tabs (far right, after Insights).
  2. In the left sidebar, scroll down and click Actions. A short menu opens beneath it.
  3. Click General under Actions.
  4. Scroll to the bottom of that page, to the heading Workflow permissions.
  5. Click the radio button for Read and write permissions. The option above it is selected by default. Change it.
  6. Click Save directly beneath those options.
Do not skip this

Without it, driver sign-ups cannot save the roster. The workflow runs, turns red, and the error is about permissions rather than anything you did.

Setting 2 — turn on the website

  1. Still in Settings, click Pages in the left sidebar.
  2. Under Build and deployment, find the Source dropdown.
  3. Click it and choose GitHub Actions. It saves itself. There is no Save button on this one.
Ignore the two cards that appear

Two boxes appear, GitHub Pages Jekyll and Static HTML, each with a Configure button. Do not click either. They would add a second, competing workflow. Choosing GitHub Actions in that dropdown is the entire setting.

A4 Publish your league page

One minute.

  1. Click the Actions tab at the top of your repository.
  2. In the left sidebar under "All workflows", click Publish site. If you still see "Get started with GitHub Actions", the .github files are missing — go back to A2.
  3. On the right, click the grey Run workflow button. A small panel drops down.
  4. In that panel, click the green Run workflow button.
  5. Wait ten seconds and refresh the page. A run appears with an amber spinner, then a green tick after roughly 40 seconds.

Your league page is now live. Replace the two capitalised parts with your own:

Your league page
https://YOUR-ORG.github.io/YOUR-REPO/

Open it. You should see the Race Hub with four cards: Sign up, Get the app, See it working, Setup handbook.

If the run goes red

Click the failed run, then the job name, and read the last red line. The usual cause is that Source under Settings → Pages was not set to GitHub Actions before running. Set it, then run the workflow again.

A5 Build the app

Three minutes, and GitHub does all of it.

The quickest route also gives you a permanent download link, so do it this way:

  1. Go to your repository's Code tab.
  2. In the right-hand sidebar, under Releases, click Create a new release.
  3. Click Choose a tag. Type v1.0.0 into the box.
  4. Click + Create new tag: v1.0.0 on publish that appears just below.
  5. In Release title, type v1.0.0.
  6. Click the green Publish release button at the bottom.
  7. Click the Actions tab. A Build Windows app run has started by itself. Three minutes. It installs Python, builds the .exe, then starts it and checks it actually serves pages before finishing.
  8. When it shows a green tick, go back to Code and click your release under Releases. PitWall.exe and PitWall-windows.zip are now attached to it.
From now on

The Download the latest release button on your league page works, and anybody in your league can get the app from it. To ship an update later, publish a new release with a new tag such as v1.0.1.

Why the build tests itself

A release that does not start is worse than no release, because you find out on race night. This one fetches the status endpoint and five pages from the built executable before it will publish it. If that fails, no release appears and the Actions log says why.

Part B

On the race PC

The Windows machine that runs iRacing. Only this person installs anything.

B1 Download and run it

Two minutes.

  1. On the race PC, open your league page and click Download the latest release.
  2. Download PitWall-windows.zip.
  3. In Downloads, right-click it and choose Extract All…
  4. Clear the box, type exactly C:\PitWall, click Extract.
  5. Open C:\PitWall and double-click PitWall.exe.
  6. If Windows says Windows protected your PC, click More info then Run anyway. This appears because the app is not code-signed. Certificates cost several hundred pounds a year.

A black console window opens and your browser opens the control panel.

Two rules

Leave the black window open while you race. Closing it stops PitWall.

Do not extract into Program Files or a OneDrive folder — Windows blocks the app writing its roster and settings there.

B2 Check it works, with iRacing closed

Do your whole OBS setup here, not on race night.

  1. Stop PitWall if it is running: click the black window and press Ctrl+C.
  2. In C:\PitWall, click once in the address bar at the top of the Explorer window, type cmd, press Enter. A black window opens already pointed at C:\PitWall.
  3. Type this and press Enter:
PitWall.exe --demo --demo-roster --speed 14

A synthetic 24-car race is now running. A full race takes about five minutes, with pit stops, a safety car and a chequered flag. Every graphic behaves exactly as it will on race night.

B3 Connect it to your roster

So driver photos and flags appear automatically. One minute.

  1. In the control panel, click the League tab.
  2. Fill in League name, and pick an Accent colour if you want. Every graphic picks these up instantly.
  3. Scroll down to the roster storage settings on the same tab.
  4. Set Mode to url.
  5. Paste your roster address into URL (url mode only) — the one you saved in A6.
https://raw.githubusercontent.com/YOUR-ORG/YOUR-REPO/main/roster.json
  1. Click Save.
  2. Click the Roster tab, then click Pull. It reports how many drivers it fetched. Zero is correct if nobody has signed up yet.
From now on

Whoever runs the broadcast in a given week gets every driver's photo, flag and bio automatically. Hit Pull at the start of race night for the latest sign-ups.

B4 Three iRacing settings

One-time. Skip the second if you only want broadcast graphics.

1. Max Cars — on the iRacing website

  1. Go to members.iracing.com and sign in.
  2. Open your Account settings.
  3. Set Max Cars to 63.
  4. Set your connection speed to 1 Mbit/s or faster.
Why this one matters most

Below 63, iRacing does not send reliable position data for the back of the field. No timing tool can invent it. If cars at the tail flicker or vanish, this is nearly always why.

2. Windowed mode — only for the in-game HUD

  1. In iRacing, open Options then Graphics.
  2. Untick Full Screen.
  3. Untick Border.
  4. Restart iRacing. Changing this without restarting often leaves a border behind.
If you race in VR

The in-game HUD cannot work in VR. A headset's compositor never sees desktop windows, so no overlay of this kind can appear inside it. This is not something that can be coded around.

Use the timing page on a phone or tablet instead. Your OBS broadcast graphics are completely unaffected and work in any display mode, VR included.

3. Telemetry — check it is on

  1. Open Documents\iRacing\app.ini in Notepad.
  2. Press Ctrl+F, type irsdkEnableMem, press Enter.
  3. It should read irsdkEnableMem=1. If it says 0, change it, save, restart iRacing.

B5 Go live

The moment of truth.

  1. Start iRacing and get into a session — a test drive, practice session or replay all work.
  2. Double-click PitWall.exe (not the demo command this time).
  3. In the control panel, click the Status tab.
If the big tile says "Connected to iRacing"

Setup is done. Every overlay, the timing page and the HUD now have real data. On to B6.

If it does not

Click the Diagnostics tab. It checks the real causes and names the one affecting you, each with its fix. Read what it says rather than searching forums — that page exists precisely because "nothing appeared and the app said nothing" is the standard experience with overlay software.

You can start PitWall before or after iRacing, either order. It watches for the sim, connects when it appears, and reconnects on its own between sessions. Leave it running all evening.

B6 Build the OBS scene

Six sources. About ten minutes, once.

Each graphic is a Browser source. Nothing to install in OBS.

The first one, in full

  1. Open OBS and select the scene you want the graphics in.
  2. In the Sources box along the bottom, click the + button.
  3. Choose Browser from the list.
  4. Type a name — Timing tower — and click OK.
  5. A properties window opens. In the URL box, select everything already there, delete it, and paste:
http://127.0.0.1:8099/broadcast/tower.html
  1. Set Width to 460 and Height to 1080.
  2. Make sure Shutdown source when not visible is unticked.
  3. Click OK. The tower appears in your scene with live cars in it.
  4. Drag it to the left edge of the canvas.

Now the other five

Identical steps each time. Only the name, URL, width and height change.

Name itURLWH
Session barhttp://127.0.0.1:8099/broadcast/session-bar.html1920120
Driver cardhttp://127.0.0.1:8099/broadcast/driver-card.html?auto=1&pos=tr19201080
Battle boxhttp://127.0.0.1:8099/broadcast/battle.html?max=1.5&pos=br19201080
Track maphttp://127.0.0.1:8099/broadcast/trackmap.html600600
Standings boardhttp://127.0.0.1:8099/broadcast/standings.html19201080
Do not resize the three full-frame ones

Driver card, battle box and standings board are 1920×1080 and position themselves inside that frame. Drop them at position 0, 0 and leave them. To move one, change its URL instead — pos=bl, br, tl or tr. Scaling a browser source makes the text soft.

The card is set to pos=tr above so it clears the tower down your left edge.

Two of them look after themselves

The driver card with auto=1 appears for eight seconds whenever you cut to a new car, then hides. The battle box with max=1.5 stays hidden unless there is a real fight closer than 1.5 seconds. Leave both in the scene permanently and never touch them mid-race.

Where to put them

  • Session bar — top of screen, position 0, 0
  • Timing tower — down the left, position 0, 120
  • Driver card — position 0, 0, leave it
  • Battle box — position 0, 0, leave it
  • Track map — bottom right
  • Standings board — put this in a separate scene for pre-race and results. It re-titles itself to RESULTS at the chequered flag automatically.

B7 Timing on a phone or tablet

Nothing to install on that device.

  1. In the control panel, click the Status tab.
  2. Scroll to the section headed On your network.
  3. Next to Live timing, click Copy. It looks like http://192.168.1.24:8099/timing
  4. Send that address to the device, or type it in by hand.
  5. Open it in any browser there.
Use the network address, not 127.0.0.1

127.0.0.1 means "this machine" and will never work from another device. Copy the one from the On your network section.

The first time, Windows asks whether to allow PitWall through the firewall. Say yes, with "Private networks" ticked. If you clicked Cancel, go to Windows Defender Firewall → Allow an app through firewall and find it there.

The page reflows into a card list on a phone. Tap any car for its profile, lap history and lap-time chart.

Drivers

Send them one link. They install nothing.

C1 What to send them

Post this in your league Discord.

Copy this, swap in your address
Sign up for the broadcast here:
https://YOUR-ORG.github.io/YOUR-REPO/

Takes two minutes and you only ever do it once.

You need your iRacing CUSTOMER ID - the number on the iRacing
website under Account > My Account > Customer ID. It is not
your name and not your car number. Everything links on that,
so a wrong one means your card never appears on stream.

You can drag a photo straight into the form. Nothing to install.

Say the customer ID part explicitly. It is the one field people get wrong, and every wrong one is a driver whose card is missing on race night.

What happens when they submit

  • A workflow reads the form, checks it, and adds them to roster.json.
  • They get a reply listing exactly what was recorded, and the issue closes.
  • Their name appears on your league page's entry list.
  • To change anything they edit their own submission and it updates automatically. No new form, no admin, no duplicates.

Drivers need a free GitHub account for this. If that is a problem for anyone, they can use the sign-up page inside the app instead — the /register address on the Status tab — while PitWall is running.

⚠ When it breaks

Diagnostics first. This is the summary.

SymptomUsually
HUD invisible in-gameiRacing in exclusive fullscreen, or you are in VR. See B4.
Everything blank, no dataiRacing not in a session, or irsdkEnableMem=0.
Back of the field flickeringMax Cars below 63 on the iRacing website.
Sim stutters with overlays onG-SYNC, or a second GPU compositing the desktop. Diagnostics explains both. Almost never the overlay's rendering cost.
Phone cannot open the timing pageFirewall, or you used 127.0.0.1. See B7.
A driver's profile missingWrong customer ID, or you have not hit Pull on the Roster tab.
Camera buttons do nothingiRacing running as administrator, PitWall not.
Graphic frozen in OBSRight-click the source → Refresh cache of current page.
Windows blocks the downloadSmartScreen. More info → Run anyway. The app is unsigned.
Gaps showing a dashWorking as intended, under caution. See below.
Track map emptyNobody has driven a clean lap there yet. It builds itself, then caches forever.
Sign-up form did nothingWorkflow permissions. See A3.
No release to downloadThe build failed its own test. Check the Actions tab.
League page 404sPages Source not set to GitHub Actions, or Publish site has not been run. See A3 and A4.
Why gaps go blank under yellow

Under caution the field is bunched behind a pace car, and a gap calculated from lap distance describes nothing real. Same for delta on any lap that touched pit lane — a car sitting in its box accumulates lap time without accumulating distance, which is how other tools end up showing a delta of +200 seconds.

PitWall shows a dash instead. A number you cannot act on is worse than no number, on a broadcast most of all.

The longer version, with the exact NVIDIA and Windows settings, is in docs/TROUBLESHOOTING.md.

PitWall reads iRacing through the SDK iRacing publishes for this purpose, read-only. Nothing is injected into the sim, no graphics API is hooked, and no game files are modified. Camera and replay control use irsdk_broadcastMsg, iRacing's own remote-control interface.

Deeper reference in the docs folder: GITHUB_HOSTING.md, OBS_SETUP.md, TROUBLESHOOTING.md.
